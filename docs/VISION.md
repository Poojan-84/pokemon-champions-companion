# Project Vision

## What we're building
A companion website for **Pokémon Champions** — the first place competitive and casual players go before building a team, prepping for a tournament, or learning the current meta.

## Why this project exists
Existing competitive Pokémon resources tend to dump raw statistics on users. Our bet is that **clarity beats completeness**. We win not by having more data than competitors, but by presenting the right information more clearly, reducing decision fatigue, and helping players act faster.

## Who we serve (in priority order)
1. New competitive players — never played ranked/tournament Pokémon before
2. Casual players — enjoy the game, curious about competitive but intimidated
3. Returning players — used to play, meta has moved on
4. Intermediate competitive players — know the basics, want faster tools

Power users and top-level competitors are **not** the initial target. We grow into serving them (Phase 3+) without ever making the site feel unwelcoming to beginners.

## The 30-second rule
Every page must answer: *"Can a first-time competitive player understand this page within 30 seconds?"* If not, the page gets simplified — advanced detail moves behind progressive disclosure (expandable sections), not onto the main view.

## How we win long-term
- **Trust** — accuracy and consistency, always up to date with the current regulation/meta
- **Speed** — fast pages, fast answers, fast mobile experience
- **SEO authority** — becoming the resource Google surfaces first for Pokémon Champions competitive queries
- **Simplicity as a moat** — competitors optimizing for "more data" will overwhelm their own users; we won't

## What we explicitly avoid
- Displaying stats because they exist, rather than because they help a decision
- Building advanced tools (damage calculators, analytics dashboards) before the fundamentals are polished
- Enterprise-grade infrastructure a solo founder doesn't need
- Feature creep disconnected from "does this help the average player decide something?"

This document rarely changes. If our target user or core differentiation shifts, update this file and note it in DECISION_LOG.md.
